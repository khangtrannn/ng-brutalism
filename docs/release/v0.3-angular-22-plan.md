# v0.3 — Angular 22 migration + signal-forms readiness plan

Decision record from the 2026-07-12 planning interview. Forms architecture rationale lives in
`docs/adr/0004-forms-support.md` (single source of truth; consolidates the original ADRs 0002/0003,
now archived); this file holds the migration decisions, audit findings, execution order, and
release gates.

**v0.3 train** = token customization overhaul (already on `refactor/token-customization`, drafted
in CHANGELOG `[0.3.0]`) **+** Angular 22 **+** the forms rework below.

## Decisions

| # | Decision | Choice |
|---|---|---|
| 1 | Driver for ng22 | Ongoing policy: track newest stable Angular each major. No ng22-only APIs in library source. |
| 2 | Peer range | ~~Rolling two-version window: `^21.0.0 \|\| ^22.0.0`~~ **Amended 2026-07-14 (ADR 0003): `^22.0.0` only.** The forms-interop story (`@angular/forms/signals/compat`) is Angular 22 API, and pre-1.0 we keep a single supported major. |
| 3 | Forms architecture | Model-based, forms-runtime-free core; `@angular/forms` leaves required peerDependencies. **Amended 2026-07-15 (ADR 0004): plus a `forms-compat` secondary entry point** (CVA bridge for `formControlName`/`ngModel` + field bridge; `@angular/forms` returns as an *optional* peer). |
| 4 | `NbSelect` contract | Good-citizen `FormValueControl` subset: `value` model + `disabled` (shipped) + **add** `touch` output (planned as "touched"; actual signal-forms name — see step 2), `invalid` input, `required` input. Structural conformance spec, no `implements` clause. |
| 5 | `NbField` | Explicit `invalid` + `required` inputs replace `NgControl` auto-detection. `NbFieldContext` / `NB_FIELD` architecture unchanged. |
| 6 | Migration path | Immediately, via Nx `23.1.0-rc.2` (`nx migrate next` — first Nx line with ng22 support; Nx ≤23.0.2 caps at `<22`). Re-run migrate at 23.1 stable. **Publishing waits for stable tooling.** |
| 7 | Release gates | (1) `minVersion < 22.0.0` scan of `dist/ui/fesm2022/*.mjs`; (2) package-smoke twice — ng21 consumer (`npx @angular/cli@21 new`) and ng22 consumer; (3) deliberate api-guard baseline update; (4) *(added 2026-07-14)* `forms-contract-check` — scoped `tsc` over `select-forms.spec.ts`, because Vitest transpiles specs without type-checking, so the conformance tripwire never fired via `nx test`. |
| 8 | Docs scope | Rewrite in place, no new pages: `forms-select-cva` → "Select with forms" (`[(value)]` primary + signal-forms example behind an *experimental* callout); `field-invalid-state` → explicit bindings; `forms-overview` → document the house contract. ## Form-component audit (2026-07-12)

`nbInput`/`nbField` do **not** overlap: clean orchestrator/consumer split via `NB_FIELD`
(field owns `controlId`/`describedBy`/`invalid`/`required`; input/textarea/label consume).
Findings that do need action:

| Finding | Where | Resolution |
|---|---|---|
| `trackControlStatus` + `NgControl` duplicated in two parallel copies | `nb-field.ts`, `nb-select.ts` | Both deleted by the rework (ADR 0002). |
| `NbCheckbox` ignores `NB_FIELD` — no `id`/aria wiring; inside `nb-field`, `nbLabel[for]` points at `field.controlId` but checkbox never adopts it → label association silently broken (live a11y bug) | `checkbox/nb-checkbox.ts` | **Proposed fix in v0.3** (copy `NbInput` pattern, ~10 lines) — pending confirmation. |
| `NbNativeSelect` — same gap, no field wiring | `select/nb-native-select.ts` | **Proposed fix in v0.3** — pending confirmation. |
| Two invalid sources when `NbSelect` sits in `nb-field` (own signal-forms-driven input vs field input) | `nb-select.ts` trigger | Precedence: either source wins — `invalid() \|\| field?.invalid()`; same for `required`. |
| Styling inconsistency (out of scope, noted only): `NbInput` uses `NbToneCapability` host directive; `NbTextarea`/`NbNativeSelect` hand-roll `data-nb-tone` | textarea, native-select | Not part of v0.3 forms work. |

Scope note: `nbInput`, `nbCheckbox`, `nbTextarea`, `nbSelect` (native) are directives on native
elements — already compatible with every forms system including signal forms; no per-control work.
`nb-rating` is display-only; no forms work. The entire custom-control surface is `NbSelect` + `NbField`.

### Amendment — 2026-07-14 forms stress-test (ADR 0003)

Pre-publish stress-test of ADR 0002 against the shipped `@angular/forms` (22.0.6 and
22.1.0-next.5) found that the widely-blogged "classic forms drive `FormValueControl`
components automatically" claim is **false** — the classic runtime has zero references to
`FormValueControl`, and no CVA adapter exists. What does exist: `[formField]` drives both
`FormValueControl` and legacy CVA components, and `@angular/forms/signals/compat`
(`SignalFormControl`, `compatForm`, `@publicApi 22.0`) bridges into classic `FormGroup`s.
Changes landed on top of steps 1–5:

- Peers narrowed to `^22.0.0` (decision 2 amended); `smoke:ui:ng21` leg removed from CI
  and `package.json`; `min-version-check` flipped to guard the ng22.0 floor (fail > 22.0.0).
- Behavioral interop specs added to `select-forms.spec.ts` (9 new): `[formField]` end-to-end
  (value both ways, schema-disabled, touched-on-close, `aria-invalid`/`aria-required`) and
  `SignalFormControl`-inside-`FormGroup` (value/touched/validity propagation). All green.
- Docs: `forms-overview` now opens with a support matrix (system × binding); "Select with
  forms" gained the reactive-forms `SignalFormControl` recipe + template-driven guidance.
- CHANGELOG `[0.3.0]` updated (Angular 22 required, interop verified); README version claims
  updated. Rationale: ADR 0003 (since consolidated into `docs/adr/0004-forms-support.md`;
  original archived at `docs/_archive/adr-0003-angular-22-minimum-forms-interop.md`).

### Amendment — 2026-07-15 adoption-risk stress-test (ADR 0004)

A second stress-test (adoption risk, verified against `@angular/forms@22.0.6` source) consolidated
the forms decisions into `docs/adr/0004-forms-support.md` — the single source of truth; ADRs
0002/0003 moved to `docs/_archive/`. Key corrections and scope changes:

- **Signal forms is stable (`@publicApi`) in Angular 22** — the "experimental" framing from
  planning (measured at 21.2.9) is obsolete. Docs drop the experimental callouts.
- **`forms-compat` un-deferred** (decision 3 amended): a secondary entry point ships in v0.3.0
  with a CVA control bridge (`nb-select[formControl|formControlName|ngModel]`, Material-style
  `NgControl` injection, submitted-aware `NB_ERROR_STATE_MATCHER` status mirroring) and an
  `nb-field` bridge for automatic error-message visibility. `@angular/forms` returns as an
  **optional** peer.
- New execution step 6 before publish: implement `forms-compat` + behavioral bridge specs
  (`formControlName`, `ngModel`, field error visibility), update the docs support matrix and
  CHANGELOG `[0.3.0]` — claims only after specs are green.

## Key facts pinned during planning

- Published `latest` is **0.2.0**; the CVA and `NgControl` auto-detect were added post-v0.2.0 and never shipped — deleting them breaks no one.
- `NbSelect.value = model(...)` has been the published API since v0.2.0 — `FormValueControl`'s only required member already ships.
- Built lib partial declarations currently carry `minVersion` ≤ `17.2.0` — far below both supported majors; the gate keeps it that way.
- Signal forms was `@experimental` at planning time (25 markers in `@angular/forms/types/signals.d.ts` at 21.2.9) but is **stable `@publicApi` at 22.0.6** (verified 2026-07-15; sole remaining experimental marker is a WebMCP provider). The type-only conformance + tripwire spec (enforced by `forms-contract-check`, **not** `nx test` — Vitest doesn't type-check) stays as a semver guard; the docs experimental callout goes.
